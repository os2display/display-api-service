# OS2Display security policy

The OS2Display development and governance teams are committed to responsible
reporting and coordinated disclosure of security-related issues.

## Reporting security issues

Please report security issues privately.

Preferred channel:
- Send an email to os2display@os2.eu.

Alternative channel:
- Use GitHub's private vulnerability reporting in the Security tab for this
  repository.

Please do not report security issues in public GitHub issues, discussions, or
pull requests.

When reporting, include:
- A clear description of the vulnerability.
- Steps to reproduce.
- Expected behavior and actual behavior.
- Impact assessment (what can an attacker do?).
- A proof of concept, logs, or screenshots if relevant.
- A suggested fix, if you have one.

## Disclosure process timeline

1. Triage: We validate whether the report is a real or likely security issue.
2. Acknowledgement: We confirm receipt and provide an initial assessment.
3. Coordination: The issue is handled in a private forum with maintainers and
   relevant governance representatives.
4. Remediation: A fix is implemented, reviewed, and tested privately.
5. Advisory and release: A coordinated release is prepared, and a security
   advisory is published when the fix is available.
6. Communication: The community is informed after mitigation details are ready.

## Scope

This policy applies to security issues in this repository
(`os2display/display-api-service`) and related deployment/runtime concerns that
materially affect the security of supported OS2Display installations.

## Response goals

While exact timelines depend on severity and complexity, we aim to:
- Acknowledge valid reports promptly.
- Prioritize high-severity issues.
- Coordinate disclosure to minimize risk for operators.
